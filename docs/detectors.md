# Detectors

## Categories
EMAIL, PHONE, PAN, AADHAAR, CREDIT_CARD, IP_ADDRESS (found from values) and DATE_OF_BIRTH (needs the column name too).
Not detected yet: names and addresses (need an NLP classifier).

## API
```python
from detectors.column_classifier import classify_column

findings = classify_column("customer_email", values)   # list of ColumnFinding, most confident first
```
Each `ColumnFinding` has: `column`, `category`, `confidence` (0 to 1), `reason`, `sample_size` (non-empty values checked) and `matched_count`. It never holds a value.

## How confidence works
ratio = matching values / non-empty values checked.
confidence = average rule confidence of the matches x ratio, plus 0.05 if the column name also hints at the category.
A column is reported only if at least 30% of its values match.

## Validators
Aadhaar uses the Verhoeff checksum, credit cards use Luhn, PAN checks the format and the holder-type letter, and IP addresses are validated with Python's `ipaddress` module.

## Date of birth
A date alone says nothing, so DATE_OF_BIRTH is flagged only when the column name suggests birth (dob, birth, born) and the values are real dates within the last 120 years. A date column named `d1` would be missed.

## Accuracy
`python -m detectors.accuracy_check --write docs/accuracy-report.md` regenerates the report. Results are on synthetic data generated by this team, so they show the rules work on this dataset, not real-world accuracy.
